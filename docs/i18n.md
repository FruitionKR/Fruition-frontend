# 다국어(ko·en)

화면 언어는 한국어(`ko`, 기본)와 영어(`en`)입니다. [next-intl](https://next-intl.dev)을 URL 접두어 없이(쿠키 기반) 씁니다. 주소는 언어와 상관없이 같습니다.

## 언어 결정

루트 `web/middleware.ts`가 화면 요청마다 정합니다(`/api`는 제외). 로직은 `web/src/shared/i18n/locale.ts`의 순수 함수이고 `web/tests/localeDecision.test.mjs`가 검증합니다.

1. `fruition.locale` 쿠키: 사용자가 랜딩 헤더나 설정 › 디스플레이 설정에서 고른 언어. 이 값만 "고정"입니다(1년).
2. `fruition.locale-auto` 쿠키: 아래 3~5로 정한 결과를 7일 동안 남겨 매 요청 다시 판정하지 않습니다.
3. IP 국가: `X-Forwarded-For` 첫 값(ALB가 붙인 클라이언트 IP)이 한국 대역이면 `ko`, 그 밖의 공인 IP면 `en`.
4. `Accept-Language`: 사설·루프백 IP(로컬 개발 127.0.0.1 등)나 해석할 수 없는 주소일 때.
5. 기본값 `ko`.

미들웨어는 정한 언어를 `x-fruition-locale` 요청 헤더로 서버 렌더에 넘기고, `web/src/shared/i18n/request.ts`(next-intl 요청 설정)가 그 값으로 메시지를 고릅니다. `<html lang>`과 메타데이터도 이 언어를 따릅니다.

사용자별 언어를 서버에 저장하는 API가 아직 없어 선택은 브라우저 쿠키에만 남습니다.

## IP 국가 데이터

- 출처: [DB-IP IP to Country Lite](https://db-ip.com/db/download/ip-to-country-lite), CC BY 4.0(상업적 사용 가능, 출처 표기 필요). 출처 표기는 랜딩 푸터의 "IP Geolocation by DB-IP" 링크입니다.
- 판정에는 "한국인가"만 필요해 KR 대역만 `web/src/shared/i18n/krIpRangesData.ts`(약 95KB, IPv4 정수 쌍·IPv6 앞 64비트)로 뽑아 미들웨어 번들에 넣습니다. 요청 때 외부 API 호출이나 파일 읽기가 없어 Edge 미들웨어에서 그대로 돌고, standalone 이미지(Dockerfile)에 따로 복사할 파일도 없습니다.
- 갱신(월 1회 공개): `web/`에서 `node scripts/update-kr-ip-ranges.mjs`. 이번 달 CSV를 받아(없으면 지난달) 파일을 다시 만듭니다. 받아 둔 파일이 있으면 `--input <dbip-country-lite-YYYY-MM.csv.gz>`.

## 문구 추가·옮기기

메시지는 `web/src/shared/i18n/messages/{ko,en}/<네임스페이스>.json`에 기능 영역별로 둡니다.

| 네임스페이스 | 화면 |
| --- | --- |
| `common` | 여러 화면이 같이 쓰는 문구(언어 이름 등) |
| `metadata` | `<title>`·description |
| `landing` | 랜딩(`src/views/landing`) |
| `auth` | 로그인·가입·인증·비밀번호 |
| `invitation` | 초대 수락 |
| `settings` | 사용자 설정(`src/features/user-settings`) |
| `legal` | 약관·처리방침 머리말과 하단 운영자 정보(본문은 한국어 원문만) |

규칙

- 키는 camelCase, `화면.부분.항목` 순으로 묶습니다(예: `settings.preferences.language.title`). 목록은 배열 대신 id를 키로 한 객체로 두고, 순서·구조는 TS 모델(예: `landingContent.ts`)에 둡니다.
- ko·en 키는 빠짐없이 같아야 하고 자리표시자(`{name}`, `{count, plural, ...}`) 이름도 같아야 합니다(`web/tests/i18nMessages.test.mjs`).
- 새 네임스페이스는 ko·en 파일을 함께 만들고 `messages/index.ts` 두 객체에 같은 이름으로 더합니다. 키 타입은 ko 메시지 기준으로 검사됩니다(`next-intl.d.ts`), 틀린 키는 `tsc` 오류입니다.
- 서버·클라이언트 컴포넌트 모두 `useTranslations("네임스페이스")`, async 서버 함수(`generateMetadata` 등)는 `getTranslations`.
- 굵게·링크가 섞인 문장은 `t.rich("key", { strong: (chunks) => <strong>{chunks}</strong> })`.
- 날짜·숫자는 직접 이어 붙이지 말고 `useFormatter()`/`getFormatter()`나 ICU(`{count, plural, ...}`)로 씁니다.
- 언어 전환은 `useChangeLocale()`(`web/src/shared/i18n/useChangeLocale.ts`): 쿠키를 쓰고 `router.refresh()`로 새로고침 없이 반영합니다.
- 서버 오류 메시지와 AI 응답은 백엔드가 만든 문자열이라 아직 한국어로 옵니다.
